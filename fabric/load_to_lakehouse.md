# Phase 2 — Unify in OneLake (SAP via mirroring, non-SAP via shortcuts)

**Goal:** land the synthetic structured data as **Delta tables** in a Fabric Lakehouse in a way
that tells the **coexistence** story: SAP arrives via mirroring/BDC (the RISE path), non-SAP via
shortcuts. In this thin demo everything is local Delta, but the `origin_system` column and the
notebook annotations keep the narrative literal.

## Lakehouse
- Name: `lh_project_intelligence` (schema-enabled — `bronze` / `silver` / `gold`).
- Created by `scripts/10_provision_fabric.ps1` with `creationPayload.enableSchemas = true`.

## What lands where

| Table | Origin system (narrative) | Production landing pattern |

| `sap_fi_cost` | **SAP** — S/4HANA Finance (RISE) | SAP BDC Connect / mirroring (zero-copy) |

## Run order (from repo root, PowerShell)

```powershell
# 0. one-time prerequisites (venv + fab CLI + az checks)
./scripts/00_prereqs.ps1
./.venv/Scripts/Activate.ps1

# 1. generate the synthetic data + unstructured corpus
python ./data_gen/generate.py           # writes out/parquet + out/csv + out/manifest.json
python ./data_gen/docs_gen.py           # writes docs/ (for Phase 4 AI Search)

# 2. author the medallion notebooks (emits fabric/notebooks/*.ipynb)
python ./fabric/notebooks/build_notebooks.py

# 3. provision Fabric access (writes SPN_* to .env). Set FABRIC_WORKSPACE_ID in .env first.
az login
./scripts/setup_spn.ps1

# 4. create the Lakehouse, upload out/parquet to Files/landing, import the notebooks
./scripts/10_provision_fabric.ps1

# 5. run the medallion notebooks (bronze -> silver -> gold)
./scripts/20_load_data.ps1
```

## Notebooks (`fabric/notebooks/`, generated by `build_notebooks.py`)
- **01_setup_lakehouse** — create `bronze` / `silver` / `gold` schemas.
- **02_load_bronze** — read each Parquet from `Files/landing/` into `bronze.<table>`; annotated
  with which tables are "SAP via mirroring" vs "non-SAP via shortcut".
- **03_build_silver_gold** — type/clean into `silver.*`, then build the fused
  **`gold.project_schedule_risk`** table plus the `gold.at_risk_activities` and
  `gold.late_procurement` driver-detail tables. `gold.project_schedule_risk` is the single
  governed table the semantic model and the agent read.

## Acceptance
- All eight structured tables appear under `Tables/` (bronze, silver) and the gold tables build.
- A SQL query joins a **SAP** table to a **non-SAP** table on `wbs_id` and reproduces the Falcon
  cross-system check (late long-lead PO + cost overrun **and** EC-1207 + negative critical-path float):

```sql
-- run against the Lakehouse SQL endpoint
SELECT TOP 5 project_id, project_name, ROUND(schedule_risk_score,1) AS score, risk_band,
       schedule_slip_days, min_total_float_days, critical_path_at_risk,   -- non-SAP
       late_long_lead_pos, forecast_overrun                               -- SAP
FROM gold.project_schedule_risk
ORDER BY schedule_risk_score DESC;
-- Project Falcon (PRJ-001) is #1, Red band, with BOTH non-SAP and SAP drivers > 0.
```
